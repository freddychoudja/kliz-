One publish. Every engine, notified.

kliz tells Bing, Yandex, Naver, Seznam, Yep and Google about your new and updated pages the moment you publish, from one URL, a list or a whole sitemap.

Reads your sitemap

Sitemaps, sitemap indexes and .gz files, from a URL or the build folder. With --since, only pages whose <lastmod> moved are sent.

One bad URL never sinks a batch

Every URL is validated and normalized before it leaves. A rejected one gets its own failed result; the rest of the batch goes out.

  • attempt 1HTTP 429 · Retry-After 30
  • waiting30 s
  • attempt 2HTTP 202

Retries the way servers ask

Opt-in retries honor Retry-After, back off with jitter and stop inside your time budget, handing back retryable=True for your queue.

Keys stay out of your logs

API keys are never logged and key file URLs show <key>. XML goes through defusedxml, and each file is capped at 50 MB.

Run it your way

Create a key, publish its file with your site, check it, then notify the whole sitemap.

  1. Generate the key into your public folder.
  2. Deploy, then verify what engines will see.
  3. Notify every page of the sitemap.
Terminal
KEY=$(kliz indexnow keygen --write public/ --site https://example.com)

kliz --indexnow-api-key "$KEY" indexnow verify-key --site https://example.com

export KLIZ_INDEXNOW_API_KEY="$KEY"
export KLIZ_INDEXNOW_KEY_LOCATION="https://example.com/$KEY.txt"
kliz notify --sitemap https://example.com/sitemap.xml

Add this to your site's repository. It runs after each successful production deployment from Vercel, Netlify, Cloudflare Pages or any host that sends deployment_status.

Providers without credentials are skipped.

.github/workflows/indexing.yml
name: Search engine indexing
on:
  deployment_status:

jobs:
  index:
    if: >-
      github.event.deployment_status.state == 'success' &&
      github.event.deployment_status.environment == 'Production'
    runs-on: ubuntu-latest
    steps:
      - uses: freddychoudja/kliz-@v0.3.1
        with:
          sitemap: https://example.com/sitemap.xml
          indexnow-api-key: ${{ secrets.INDEXNOW_KEY }}
          indexnow-key-location: https://example.com/${{ secrets.INDEXNOW_KEY }}.txt
          gsc-site: https://example.com/
          gsc-service-account-json: ${{ secrets.GSC_SERVICE_ACCOUNT_JSON }}

Synchronous and framework-agnostic. Call it from a view, a Celery task, a cron job or a serverless function.

notify_many deduplicates, groups by host and splits by each provider's batch limit.

Python
from kliz import IndexNowProvider, Kliz, read_sitemap

indexer = Kliz(
    [
        IndexNowProvider(
            api_key="your-indexnow-key",
            key_location="https://example.com/your-indexnow-key.txt",
        ),
    ],
    max_attempts=3,
)

with indexer:
    indexer.notify_all("https://example.com/articles/new")
    indexer.notify_many(read_sitemap("https://example.com/sitemap.xml"))

Commands

Common questions

  • No. It asks the engine to crawl the page soon; whether and when it is indexed stays the engine's decision. Accurate sitemaps and honest <lastmod> dates help most.

  • Google reserves it for job postings and livestreams. For every other page, kliz resubmits your sitemap through the Search Console API, which is the supported route.

  • At the root of your site as <key>.txt, served with HTTP 200 and no redirect. kliz indexnow keygen --write public/ creates it, and verify-key checks it after you deploy.

  • Use --since, or the Action's since input, to send only pages whose <lastmod> moved. Remembering what was already sent is on the roadmap.

  • Yes. Inherit from BaseProvider, or from BatchProvider for engines that take batches. Validation, normalization and the shared HTTP session come for free.

  • Yes. The command line runs in GitLab CI, a cron job or a container, and the library runs inside any Python 3.10+ application.
